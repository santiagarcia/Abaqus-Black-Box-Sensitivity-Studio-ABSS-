1. What ABSS does

You have an Abaqus/Standard model. ABSS tells you how every result of that analysis changes when a model parameter changes: displacements, reactions, stresses, strains, plastic strain and state variables, at every accepted increment. Parameters can be a Young's modulus, a yield stress, a load, a prescribed displacement, a node set's position, or an opaque constant of a compiled user material.

For each parameter a and each output F, ABSS computes the derivatives dF/da, and optionally d²F/da² and mixed derivatives, as full fields over the mesh and over time. You look at them in the same window as colour maps on the deformed mesh and as history curves at points you click.

ABSS does not re-implement any Abaqus element or material. Abaqus does every mechanical computation; ABSS only decides which small Abaqus jobs to run and how to combine their answers. Everything runs on your computer.

2. How it works

The idea is to use Abaqus as a residual oracle. Each step below is something ABSS makes Abaqus do.

  1. Nominal analysis. ABSS runs your model once, unchanged except for extra output requests and tight equilibrium tolerances. The accepted increments define the time grid on which all derivatives are taken.
  2. Probe jobs. To ask "what is the out-of-balance force if the structure were in this shape, with this parameter value?", ABSS restarts Abaqus from the previous increment and prescribes every degree of freedom. Abaqus then reports the reaction forces, which are exactly the residual r = −RF. These short jobs are the only way ABSS talks to Abaqus.
  3. History branches. For every perturbed parameter value (a ± h, ± 2h, …) ABSS keeps a separate chain of restart files. Plasticity, damage and every other history effect is therefore integrated by Abaqus on the perturbed path, so the derivatives are history-consistent.
  4. Sensitivity solve. At each increment ABSS combines the probe residuals with a finite-difference stencil and solves K u' = −∂r/∂a for the displacement derivative. K comes from Abaqus's own element matrices. When that matrix is not the true tangent (plasticity, hyperelasticity under NLGEOM, constraints, dynamics), ABSS detects the mismatch and solves matrix-free with GMRES, using more probe jobs instead of the matrix.
  5. Commit. Each branch advances to its first-order predicted state; the field outputs of those commits, combined with the stencil, give the derivatives of every output field.
  6. Checks. Every run measures its own consistency: a tangent check, a predictor-consistency ratio, a nominal replay check and a non-smoothness detector. With "Validate" switched on, ABSS also re-runs complete Abaqus analyses at a ± h and compares every value at every increment. Each result then carries a badge: Validated, Experimental, Unverified or Failed.

The full mathematics, with the derivations and the Council review, is in docs/SCIENCE.md.

3. Installing

Each platform has one file that installs everything.

PlatformRunYou do
WindowsABSS-Setup-<version>.exeApprove the administrator prompt, and accept the Microsoft and Intel compiler licences once. For IT deployment with no questions at all: ABSS-Setup.exe /S /ACCEPT_LICENSES.
Linux workstationbash ABSS-Installer-Linux-<version>.runNothing. It needs no root rights; it installs a private toolchain into ~/abss, builds and tests ABSS, and adds abss and abss-cli to your PATH.
HPC clusterthe same .run on a login nodeNothing. It builds the headless abss-cli and writes an environment module (module load abss) and a Slurm job template; the cluster's module load abaqus is used automatically.
  1. On Windows the installer finds Microsoft C++ Build Tools and Intel Fortran, or downloads and installs them. Parts already present are skipped. Prebuilt libraries and models without user subroutines don't need them.
  2. Abaqus itself is found automatically (C:\SIMULIA\Commands\abaqus.bat, or set ABSS_ABAQUS_CMD). The built-in demos work without Abaqus.
  3. Linux-only material libraries (.so) run natively through ABSS's ELF host; nothing else is needed. Only a library that reads input files at run time needs WSL (administrator PowerShell: wsl --install -d Ubuntu).

4. Using the application, page by page

The left bar takes you through five pages in order. Each page tells you what is missing before you can go on, so you cannot start a run that is set up wrong.

Start

Parameters

  • Known parameters have a physical meaning, for example "ALU: E".
  • Indexed ones are opaque: "UMAT NH: PROPS[3]" is a position in a compiled material, and ABSS never invents a name for it.
  • Unsupported rows (shown greyed when "Show unsupported" is on) explain why they cannot be perturbed.

Set up

Run

The Run page shows progress per increment, a live log and a Cancel button; the window stays responsive. If something cannot work (a missing subroutine, an unsupported feature, a licence problem), the page explains it in plain language and says what to do, instead of producing numbers.

Results

From here you can export CSV, PNG and VTU, or save the whole result as .abss. A saved result reopens later without Abaqus. The results folder of this package contains one for every verification case: open any of them with File → Open.

5. The same from the command line

abss-cli inspect model.inp                         # list parameters and their ids
abss-cli run model.inp --params "mat:STEEL:elastic:E,load:LOAD:cload:TIP:1" --order 2 --jobs 4 --validate --out run.abss
abss-cli show run.abss                             # evidence summary, no Abaqus needed
abss-cli usersub my_umat.f --out mylib             # build a reusable UMAT library once
abss.exe run.abss                                  # open the result in the GUI

A compiled material Abaqus cannot load: a Linux .so, or a .dll with its own interface (e.g. a deformation-gradient update + state initialiser)generates a UMAT/SDVINI that forwards each call to a helper process running the library (material bridge), and checks the sizes declared in the library's header against the model. A Linux .so runs natively in ABSS's ELF host: no Linux, no WSL.C++ build tools

ABSS builds these libraries itself, so they work even though this Abaqus installation lacks its own user-subroutine development files. Only the opaque constants (PROPS) are differentiated. The source is never read and nothing is uploaded.

7. What has been verified

Every case below was run on real Abaqus 2024 with the build in this package, and validated by comparing every derivative at every increment and every node or integration point against central differences of complete Abaqus re-analyses. The tolerance is 1e-3 relative. The exact numbers, per field, are in results/SUMMARY.md and the full logs next to it.

How long it takes, compared with plain finite differences

Measured on the same machine, with 3 Abaqus jobs at a time for both methods. On these small models, ABSS was 1.3 to 61 times slower than finite differences of complete Abaqus re-analyses. Examples:

  • Truss at order 2: 145 s against 115 s.
  • Thermal stress: 495 s against 51 s.
  • J2 plasticity: 3,664 s against 60 s.

Every Abaqus job costs 15 to 20 s of start-up here, and less than a second of solving. ABSS runs several single-increment restart jobs per increment, while finite differences need two full jobs per parameter. ABSS can only be faster on large models, where one full analysis costs far more than a job start-up; that has not been measured yet. The full table and the cost model are in docs/VALIDATION_RESULTS.md §3.8.

9. What is not supported, and why

  • RIKS: the load factor is itself an unknown of the arc-length method, so there is no fixed load path to differentiate along.
  • Explicit dynamics, heat transfer, coupled procedures: they have no displacement residual that this oracle can evaluate.
  • Implicit dynamics combined with constraints: the inertia of tied or coupled nodes reaches their masters only through constraint equations that Abaqus does not expose.
  • Amplitudes or temperatures computed at run time (solution-dependent, user subroutines, read from another results file): ABSS cannot re-evaluate them at its own increments.
  • Non-smooth events (yield onset, contact opening) make derivatives one-sided. ABSS flags those increments instead of smoothing them away.

Everything ABSS cannot do is refused with the reason, not approximated. See docs/KNOWN_LIMITATIONS.md.
